**第 1 题**：`git add` 和 `git commit` 为什么要分成两步？合并成一步不行吗？（提示：想想暂存区存在的意义）

我的回答：add添加到暂存区后如果想修改很方便，提交后修改麻烦
暂存区真正的意义是——让你挑选"这次提交什么"​。

举个真实场景：你今天改了 3 个文件，其中一个改到一半、是个半成品。

有暂存区：你只 add 那两个做完的，半成品留着下次。​半成品不会污染你的提交记录。
假如 add 和 commit 是一步：你只能要么全提交（把半成品也带上），要么全不提交。

**第 4 题**：`if / elif / else` 里，把 `elif` 换成另起一个 `if`，结果会一样吗？有什么区别？

我的回答：不一样，会有一个全新的条件语句

> 批注（小鲸鱼）：方向对，但**关键差别没说透**。
>
> `elif` 是**互斥**的：前面命中，后面全部跳过 —— 一条链**最多只执行一个分支**。
> 另起 `if` 是**独立判断**：前面命中了，后面**照样会判断** —— 可能同时执行好几个分支。
>
> ```python
> x = 35
> if x > 30:    print("A")   # 命中
> elif x > 20:  print("B")   # 被跳过
> # 输出：A
> ```
>
> ```python
> x = 35
> if x > 30:    print("A")   # 命中
> if x > 20:    print("B")   # 照样判断，也命中
> # 输出：A 和 B
> ```
>
> 这正是你今天 `day3_if.py` 那个 bug 的根源：`elif` 链上一旦命中，后面的条件再宽松也轮不到。

**第 3 小时 · 列表与字典**

**第 5 题**：列表和字典分别适合装什么样的数据？各举一个你项目里（物联网平台）可能用到的例子。

我的回答：列表装同类型的（传感器1，传感器2），字典装一个东西的不同属性（传感器（名字，温度，状态））

> 批注（小鲸鱼）：**满分**，例子举得准。
> 补两个术语，方便面试时说出口：列表适合装「**同类型的一批东西**」，字典适合描述「**一个实体的多个属性**」。
> 在你项目里的对应很清楚——MQTT 收到的**一条**设备报文 = 一个字典（里面有 name、temperature、online 等字段）；
> 一段时间收到的**多条**报文 = 一个列表，里面装着许多个这样的字典。


**第 6 题**：要取列表的最后一个元素，可以写 `devices[-1]`。为什么 `devices[len(devices)]` 是错的？

我的回答：len（device）是列表的长度（如5），而列表是从0开始，会比长度少1（只有4），所以报错

> 批注（小鲸鱼）：**对的**。
> ① 精确叫法：抛出的异常是 `IndexError: list index out of range`，面试时报全名更好。
> ② 顺带记住：`devices[-1]` 其实就是 `devices[len(devices) - 1]` 的简写——
> Python 用负数索引从末尾往回数，`-1` 是最后一个，`-2` 是倒数第二个。
